## 핵심 검증 내용

### AdSpec / WINDLY

규칙 버전별 입력 판정, 공식 규칙과 시연용 정책 분리, 정확한 소수 금액에서 정수 micros로의 변환, 잘못된 JSON·타입·날짜 처리, 현재 입력과 규칙에 연결된 검토 상태를 검사합니다. 수정 제안은 명시적인 적용 동작으로만 입력에 반영됩니다.

### FlowMap / INTERX

업무 단계 순서·쓰기 범위·승인 위치를 검사하고 승인 전 쓰기 차단, 같은 작업의 중복 실행, 실패 후 재시도를 재현합니다. 주간 시간 추정은 건수·검토 시간·실패 확률·유지 시간을 입력 가정으로 공개합니다.

### BriefLedger / DOCENTY

브리프와 요구사항·정상·오류·권한 거부 시나리오 연결을 9개 구조 규칙으로 검사합니다. 입력 변경 시 이전 검사와 검토 기록이 현재 상태를 통과한 것처럼 사용되지 않도록 확인합니다.

### AvatarOps / ENSAPIA

실행 기록의 사용자 범위, 도구 허용 목록, 호출과 결과의 연결, 완료 근거, 중복 적용, 승인 순서, 시간, 재시도, 버전 근거를 검사합니다. 시나리오·fixture·정책·규칙 버전이 같은 기록끼리만 결과 차이를 비교합니다.

### StockBridge / VIBERS

CSV 파싱·명시적 열 연결·누락값·수량·통화·정확한 소수 단가·동일 중복·충돌 중복·SKU와 지역별 식별을 검사합니다. 수량 차이의 부호와 금액 차이의 절댓값을 구분하고 통화가 다른 금액을 합산하지 않습니다. 내보내기는 현재 대사 입력에 연결됩니다.

### FaultLab / WISEWIRES

수량 경계, 과도한 할인, 중복 주문, 만료 시각, 오래된 검색 응답, 중복 환불을 결함 구현과 수정 구현에 같은 입력으로 실행합니다. 별도의 업무 규칙이 기대값을 계산하므로 수정 함수를 그대로 따라가는 테스트로 구성하지 않았습니다. 의도된 결함의 재현 실패와 프로젝트 테스트 실패를 구분합니다.

## 독립적인 입력·내보내기 코드 검토

별도의 소스 검토에서 아래 위험을 재현하거나 확인했고 방어를 반영했습니다.

| 위험 | 반영한 처리 |
| --- | --- |
| 깊게 중첩된 저장 JSON이 복원 후 재귀 스냅샷에서 오류를 만들 수 있음 | 저장 복원 시 문자열 1,200,000자, 깊이 32, 총 노드 20,000 제한과 실패 시 기본값 복원 |
| AdSpec의 깊은 JSON·큰 관측값을 오류 보고서에 그대로 넣으면 렌더링이나 JSON 직렬화가 실패할 수 있음 | 원본 입력의 깊이·노드·문자열 제한과 짧은 안전 관측값 사용 |
| StockBridge의 큰 중복 그룹이 오류 문장을 제곱 규모로 늘릴 수 있음 | 중복 그룹 누적 방식 개선, 오류의 원본 행 목록을 최대 20개까지만 표시 |
| 열이 과도한 CSV가 열 연결 UI를 부풀릴 수 있음 | 최대 128개 열 제한 |
| CSV를 스프레드시트에서 열 때 셀 문자열이 수식처럼 해석될 수 있음 | 위험한 시작 문자와 앞 공백을 고려한 문자열 접두 처리, 큰따옴표 이스케이프 |
| 입력 변경 후 이전 검토·내보내기를 현재 결과로 오인할 수 있음 | 현재 입력 스냅샷 또는 현재 실행에 결과를 연결하고 변경 시 재검토·재실행 요구 |
| 허용하지 않은 경로에서 임의 모듈을 불러올 수 있음 | 회사 ID·탭 이름 허용 목록, 알 수 없는 주소의 복구 화면 |

소스 검토에서 모듈의 `eval`, `new Function`, `dangerouslySetInnerHTML` 또는 입력을 외부 API로 보내는 런타임 호출은 사용하지 않았습니다. React 텍스트 출력과 브라우저 Blob 다운로드를 사용하며 다운로드 후 객체 URL을 해제합니다. 이 검토는 전 범위 보안 감사나 모든 환경의 호환성 검증을 뜻하지 않습니다.

## 실제 브라우저 확인 범위

공개 배포에서 수행한 동작을 아래에 기록합니다. Node 테스트와 구분한 데스크톱 브라우저 관측이며, 모바일·전체 경우의 자동 완주를 뜻하지 않습니다.

| 도구 | 직접 수행한 동작과 관측 |
| --- | --- |
| AdSpec | 초기 규칙 실패 3개에서 HTTPS·UTM·예산 수정으로 0개 도달. 승인 뒤 예산 30000→30001 변경 시 재검토 요구, 새로고침 후 값 유지. 잘못된 JSON에서 승인·보고서 제한, 예제 복구. 화면의 fixture 회귀 11/11 일치. 7,246바이트 JSON 다운로드를 읽어 현재 입력·판정·승인 상태를 확인. |
| FlowMap | 승인 전 전달 0건, 승인 후 1건, 동일 실행 재사용 시 추가 0건. 장비 ID 누락 차단. 주간 요청 0건에서 유지 시간 때문에 불리한 결과가 나오는 계산도 그대로 표시. 음수 입력 시 보고서 제한. 실제 실행 Markdown과 회사별 설명 Markdown의 내용을 확인. 설계·출처 탭 탐색 확인. |
| BriefLedger | 완성 예제의 9개 검사 통과, 현재 브리프 검토, 입력 변경 시 기존 검토·검사 근거 무효화, 현재 JSON 근거 파일 생성 확인. |
| AvatarOps | 기본 합성 기준 기록의 실패·이벤트별 근거 확인. 후보로 전환해 7개 통과·0개 실패·2개 미평가 확인. 잘못된 JSON에서 비교·다운로드 차단과 예제 복구. 16,825바이트 JSON을 읽어 동일 조건 1쌍, 개선 1개, 회귀 0개와 합성 시간 차이를 확인. |
| StockBridge | 실제 CSV 파일 선택·업로드 후 2행·유효 고유 2건·일치 1건·차이 1건, USD 5·KRW 0 확인. 검토 뒤 실사 수량 8→9 편집 시 검토 무효화와 검토·CSV·JSON 동작 제한 확인. 재대사·재검토 후 USD 2.5·KRW 0, 수량 차이 -1. 실제 CSV 418바이트와 JSON 3,460바이트를 읽어 현재 입력·계산·검토 스냅샷 일치를 확인. [상세 기록](QA_STOCKBRIDGE.md). |
| FaultLab | 기본 입력 6개에서 결함 6개 재현·수정 6개 통과. 할인 5000에서 결함 결제액 -4000과 수정 0 비교, Markdown 보고서 내용 확인. 할인 500으로 변경하면 이전 결과 제거, 재실행 후 두 구현 통과와 결함 보고서 제한. 숫자 공란에서 입력 오류와 판정 부재, 예제 복구 확인. |

일부 다운로드 이벤트 대기는 시간이 초과되었지만 파일은 실제로 저장되었습니다. 위 다운로드 결과는 저장된 파일의 내용 확인에 근거합니다. 검사한 콘솔에는 브라우저 확장 기능의 메타데이터 메시지가 있었으며 확인한 표본에서 앱 출처 오류는 관측하지 않았습니다. 따라서 “전체 콘솔 오류 0”으로 표현하지 않습니다.

독립 브라우저 검토에서 FaultLab의 잘못된 숫자 입력 직후 상태 안내 문구가 과도하게 일반적이라는 지적을 받았습니다. 입력 오류·판정 부재·다운로드 제한은 정상 동작했으며, 이후 안내 문구를 수정해 재배포했습니다. 마지막 문구 변경은 배포 READY와 저장된 소스의 일치로 확인했고 별도의 전체 브라우저 회귀 수행을 주장하지 않습니다.

초기 페이지의 웹·모바일 이미지는 배포 플랫폼에서 제공되었습니다. 여섯 도구의 모바일 편집·파일 업로드·터치 조작은 확인하지 않았으며 후속 검증 범위로 남깁니다. 서로 다른 브라우저·운영체제, 실제 API 연동, 부하·동시성 시험도 이 릴리스의 범위 밖입니다.

## 재현 명령

Node.js 24 환경에서 `employer-workbench/`로 이동한 뒤 실행합니다.

```bash
npm ci
npm test
npm run typecheck
npm run build
npm run preview
```

`package-lock.json`을 포함해 설치 기준을 고정했습니다. 산출물 `dist/`와 설치된 `node_modules/`는 소스 배포에 포함하지 않습니다.

## 공개 범위와 운영상 한계

모든 기본 시나리오는 합성 데이터이고 계산·검사는 브라우저에서 실행됩니다. 외부 모델·실제 회사 서비스·광고 계정·ERP·고객 데이터베이스 연결과 실제 업무 변경을 수행하지 않습니다. 로컬 검토 상태는 사용자 신원·전자서명·운영 서버 감사 기록이 아닙니다.

AppDeploy의 공개 주소를 사용합니다. `vercel.json`은 이식 가능한 정적 빌드 설정이며 Vercel 유료 서비스나 배포를 생성한 기록은 없습니다. GitHub 배치는 기존 프로젝트를 바꾸지 않는 새 브랜치의 별도 폴더로 제한합니다. 이메일·지원서 전송은 이 릴리스의 검증 범위에 포함하지 않습니다.
